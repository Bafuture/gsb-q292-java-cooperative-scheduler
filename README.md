## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

我们的业务任务需要在可控的位置主动让出，避免某个任务长时间独占线程。请从零实现一个协作式轻量任务调度器。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ）。要求：1) 任务以可恢复的单元形式编写，在显式让出点挂起，由调度器决定何时恢复；2) 支持固定优先级与轮转两种调度策略，策略可配置；3) 让出点必须可枚举：调度器能记录每个任务执行过的让出点，用于复现执行路径；4) 支持任务取消：在让出点检查取消标志，取消后不得再执行任务体的后续部分；5) 支持公平性验证：等优先级任务在轮转策略下不得被长期饿死，需有测试证明；6) 支持统计：调度轮次、每个任务的执行次数、让出次数与平均每次连续执行步数；7) 说明协作式调度的局限（任务不主动让出就无法被打断），并给出实现建议；8) 测试覆盖挂起恢复、两种策略、取消、公平性、路径可复现与统计；`mvn -q verify` 一条命令跑通。


## 实现说明

### 核心模型

任务以「步骤（step）+ 显式让出点（yield point）」的可恢复序列编写：

```java
CooperativeTask task = CooperativeTask.builder("report")
        .priority(5)                                   // 固定优先级策略下生效，默认 0
        .step(ctx -> loadData())                       // 一段同步工作
        .yieldPoint("data-loaded")                     // 显式让出点：在此挂起
        .step(ctx -> {                                 // 恢复时从这里继续
            if (ctx.isCancelled()) return;             // 长步骤内可协作式检查取消
            render();
        })
        .build();

CooperativeScheduler scheduler = CooperativeScheduler.builder()
        .policy(SchedulingPolicy.ROUND_ROBIN)          // 或 FIXED_PRIORITY，默认 ROUND_ROBIN
        .addTask(task)
        .build();

scheduler.cancel("report");   // 在下一个让出点（调度边界）生效
scheduler.run();              // 或 runRounds(n) 限量调度
SchedulerStats stats = scheduler.stats();
```

- **挂起与恢复**：调度器为每个任务维护游标，执行到让出点即挂起并交还线程；恢复时从让出点之后继续，已执行的步骤不会重复执行。
- **调度策略**：`FIXED_PRIORITY` 每次选择优先级最高的就绪任务（同优先级按注册顺序）；`ROUND_ROBIN` 维护 FIFO 就绪队列，队首执行一轮后回到队尾，等优先级任务在一个完整循环内必然各得到一次执行，不会被饿死（见 `FairnessTest`）。
- **路径可复现**：每个让出点有唯一 id；调度器记录全局轨迹 `yieldTrace()`（轮次 + 任务 + 让出点）与单任务轨迹 `yieldHistoryOf(name)`，相同输入重放得到完全相同的路径（见 `PathReproducibilityTest`）。
- **取消**：`cancel(name)` 只置标志，在调度开始与让出点两处边界检查；取消后任务状态为 `CANCELLED`，任务体后续部分不再执行（见 `CancellationTest`）。
- **统计**：`SchedulerStats` 含调度轮次与全局轨迹；`TaskStats` 含每任务执行次数、让出次数、累计步数与平均每次连续执行步数（累计步数 / 执行次数）。

### 协作式调度的局限

1. **无法抢占运行中的步骤**：调度只发生在让出点。若某个 step 长时间运行（或死循环）且不让出，它会独占线程直到结束，其他任务全部饿死——这正是协作式调度的根本局限。
2. **让出依赖任务自觉**：让出点的位置与密度由任务作者决定，调度器无法强制。
3. **取消不是即时的**：`cancel` 只在让出点生效；正在运行的 step 会跑完。
4. **单线程**：本调度器是单线程事件循环，不利用多核；要并行需结合抢占式机制（线程池）。

### 实现建议

- **小步快跑**：把长任务拆成多个小 step，在 step 之间插入让出点，控制单步耗时上界。
- **长步骤内自查**：无法拆分的循环在 step 内部通过 `TaskContext.isCancelled()` 定期检查取消标志并提前返回。
- **让出点命名稳定**：让出点 id 是执行路径的标识，应稳定、可读、在任务内唯一，便于回放与审计。
- **需要硬抢占时换机制**：对不可信或不可控的任务体，改用抢占式方案（独立线程 + 超时中断、或进程隔离），协作式调度只适用于任务体可信且配合的场景。
- **公平性用轮转**：对延迟敏感、等优先级的任务使用 `ROUND_ROBIN`；`FIXED_PRIORITY` 下低优先级任务可能被高优先级任务长期压制，仅用于有明确优先级的场景。
